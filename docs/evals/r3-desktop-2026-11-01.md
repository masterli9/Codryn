Finální série směla po výslovném rozhodnutí rodičovského agenta využít nejvýše **0,11924679 USD**, tedy pět podílů po 0,023849358 USD. Od společného limitu se předem odečetly plné konzervativní rezervy obou neúspěšných sérií, dohromady zaokrouhlené nahoru na 0,130753201 USD; součet všech maxim byl 0,249999991 USD. Jednorázový exclusive `final-series-started.json` zabránil dalšímu spuštění stejné série. Další placené běhy se neprováděly.

Všechny série používaly skutečný distribuční Electron, React, preload, IPC a backendové služby, nový chráněný profil a nový syntetický projekt pro každý pokus; tři Git a dva non-Git v každé sérii. Native folder a close dialogy nahrazoval pouze test driver v main procesu. To nenahrazuje osobní autorskou kontrolu systémového dialogu. Klíč se zadal do skutečných Nastavení a po uložení bylo ověřeno vyprázdnění password pole. Samostatný placený Test připojení se neprováděl.

První série chybně považovala opožděně odstraněné tlačítko „Povolit jednou“ za nové oprávnění a při nulovém backendovém pending požadavku spustila úklid. [Read-only kontrola skutečné databáze](../../.r3-artifacts/2026-11-01-e3-live/protocol-T66rKU/harness-diagnosis.json) prokázala v každém pokusu právě jedno trvalé `allowed_once`, jednou převzaté oprávnění, úspěšné search/read/patch a příkaz zrušený úklidem. Původních 0/5 zůstává zachováno. Oprava pozorovatele pracuje s ID/digestem a ignoruje staré tlačítko bez nové backendové žádosti; změněný digest, více pending žádostí nebo neočekávaný příkaz nadále odmítá. Offline regrese a finanční brána prošly společně 10/10; [lokální výstup](../../.r3-artifacts/2026-11-01-e3-live/offline-tests.log).

Druhá série měla v každém pokusu právě jedno schválení; search/read/patch i příkaz uspěly, `exitCode:0`, procesní strom byl potvrzený jako zastavený. Testovací zadání ale požadovalo `C:\nvm4w\nodejs\node.exe`, zatímco jeho kanonický cíl je `D:\nvm\nvm\v24.19.0\node.exe`. Backend runtime správně používá kanonickou cestu a referenční verifier vyžaduje její přesnou shodu. Uložený důvod proto zní `Command is not a trusted project verification check.` Výsledek zůstal `unverified` a běh `failed`; GUI diff a návrat ovladač nedosáhl. To je chyba přípravy ovladače, nikoli důvod oslabit produkční ověřování.

Po obou neúspěšných sériích používá ovladač `realpath(process.execPath)` v zadání i v přesné kontrole schvalovaného příkazu. **Jeden následný čistě offline průchod stejným ovladačem prošel 1/1:** [skutečný packaged DEMO protokol](../../.r3-artifacts/2026-11-01-e3-live/offline-8RyaA7/report.json). Prokázal kanonický executable, právě jedno oprávnění, reload se zachovanou identitou, aktuální `verified`, viditelný diff, úspěšný `change.revert`, přesné původní soubory a zachovaný Git HEAD/status. Brána odmítala veškeré API volání; zaznamenala nula požadavků a nulovou rezervu. Skutečný API klíč se při tomto průchodu nenačítal ani nezadával. To ověřuje opravu ovladače, nikoli nový live úspěch nebo doplnění neúspěšných sérií.

Ve finální sérii uspěly pokusy 1, 2, 3 a 5: skutečný search/read/patch, jednou převzaté oprávnění, příkaz s exit 0 a potvrzeným procesním stromem, aktuální ověření, viditelný diff a návrat přesných původních souborů. Git HEAD/status zůstaly zachované. Pokus 4 se do úspěchů nepočítá: dosáhl skutečného `completed`/`verified` a správného příkazu, ale ovladač požádal klávesnicí o návrat dříve, než se dorovnala rendererová projekce. [Skutečný screenshot](../../.r3-artifacts/2026-11-01-e3-live/protocol-ktbWgE/attempt-4/verified.png) stále ukazuje „Čeká na model“, krok 4/12 a **disabled** tlačítko návratu; focus+Enter neodeslalo žádný návratový požadavek. Databáze obsahuje jen zápis změny, žádný `change.revert` call ani revert událost; po zavření zůstalo `a + b` a nezměněný test. Nešlo o selhání již spuštěného produktu při návratu, protože návrat vůbec nebyl vyžádán. Jde o chybu testovacího ovladače; skutečné 4/5 zůstává beze změny a `safeReturn:false` se nepřepisuje na úspěch.

V prvním pokusu každé série se skutečně obnovil renderer při čekajícím oprávnění a zachovala se stejná ID/digest identita; v ostatních pokusech se reload znovu neprováděl. Pozorování neprázdného modelového textu ve stavu streamování před dokončením nebylo pollingem prokázáno. `streamBeforeCompletion:false` v přenosném JSON znamená „nezměřeno“, nikoli důkaz chybějícího streamování. `diff:false` a `safeReturn:false` druhé série označují nedosažené kroky po neúspěšné verifikaci. Nový současný live důkaz streamovaného textu zůstává mezerou E3.

Po zavření všech vlastních aplikací proběhl scan přesného skutečného klíče v UTF-8 i UTF-16LE: **334 + 334 + 339 souborů**, dohromady **1007**, žádný nález a žádný nečitelný či vynechaný soubor. Obsah chráněného úložiště ani ostatních souborů se nevypisoval. Následný scan publikovaných pracovních souborů se eviduje samostatně v lokálním `published-secret-scan.json`.

Následný scan všech aktuálně změněných a nových neignorovaných Git souborů prošel: **16 souborů, nula nálezů a nula nečitelných či vynechaných souborů**. Přenosné JSON byly ověřeny pomocí již nainstalovaného AJV 2020-12 s validací datumových formátů; finální protokol navíc porovnává skutečné DB nástroje, oprávnění, procesní výsledky, návrat, scany a finanční ledger. Příprava budoucího ignorovaného ovladače doplnila čekání na povolení tlačítek a zánik „Zastavit“ před návratem; po této úpravě se žádný placený pokus neopakoval.

Finanční brána je dočasná testovací instrumentace main `fetch`, nikoli dodaná produktová funkce. Povoluje jen POST na přesné Responses URL, model `gpt-6-luna`, `store:false`, streaming a nejvýše 4096 výstupních tokenů; redirect odmítá. Před každým HTTP požadavkem včetně retry atomicky rezervuje celý počet UTF-8 bytů requestu plus 4096 framing tokenů a maximální výstup. Request má nejvýše 128 KiB, limit je 12 HTTP požadavků a 12 modelových kroků na pokus, celkový deadline 180 s na pokus. Konzervativní tokenový odhad není přesný tokenizer ani poskytovatelův účtovací strop. Druhá série odečetla první rezervu z původního společného limitu; rezervy se po chybě nevracejí.

Žádný z těchto protokolů nezatrhává osobní autorský checklist ani nedokládá celé R3/O1. Další placené volání vyžaduje nové konkrétní rozhodnutí při zachování dosavadních reportů a kumulativního limitu. Samostatné packaged vizuální QA obou motivů na třech velikostech má vlastní protokol.
