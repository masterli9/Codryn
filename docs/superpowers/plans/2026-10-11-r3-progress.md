# R3 — rozpracovaný checkpoint 2026-10-11

## Novější ověření — 29. října 2026

Třetí bod pokračování je implementovaný a ověřený: R0 diagnostiky v UI,
návrat z vytížených nastavení k aktivnímu běhu i po obnově rendereru,
editovatelný retry s ochranou celého odesílaného požadavku a načtené aktivity.
Čistý implementační subagent i nezávislé review; jeden nalezený problém
ztráty novějšího konceptu byl opraven a znovu zkontrolován.
Závěrečná sada 632 passed / 3 skipped, typecheck/lint/deps prošly
(306 modulů / 928 vazeb). MCP ověřilo tři šířky a oba motivy nad produkčními
komponentami se syntetickými daty; package tím doložen není. Podrobnosti jsou v
[záznamu třetího kroku](2026-10-29-r3-step3-ui.md).
Aktuální pokračování začíná bodem 4 níže. Package, skutečné Electron UI E2E
a celá brána R3 zůstávají neověřené.

## Implementováno, ještě vyžaduje celkové ověření

- A1–A3: striktní sdílené kontrakty/IPC, backendové porty a chat služba,
  migrace 10–12, transakční identita požadavků, historie, projekce, stránkování,
  omezené snapshoty/výstupy, subscription cursory a trvalé action intents.
  Migrace 0–9 zůstaly zachovány.
- B1–B4: společná databáze a čerstvé R2 runtime instance, jediný RunAgentLoop,
  vlastnictví běhů, projektové refresh, reference-only verification, validovaný
  model stream, redakce/dávkování, permission broker, skutečný průběžný výstup
  příkazů, Windows Job ownership ACK před spuštěním, cancel a recovery bez replay.
- C1–C3: Electron safeStorage/Windows DPAPI, šifrovaná obálka, ACL, atomická
  náhrada, metadata/verze/lease/souhlas, ukládání/odstranění klíče, explicitní
  connection test, provider factory a ověření systémového Node runtime.
  Žádný plaintext fallback ani skutečný placený API test se neprováděl.
- C4: main/preload integrace, validace odesílatele a hlavního frame, bezpečné
  chyby, omezené odběry s ACK, sandbox rendereru a řízené uzavření aplikace.
- D1–D3: React pracovní plocha, lokální Instrument Sans, vlastní SVG ikony,
  projekty/chaty/historie, composer, běhy, aktivity, oprávnění, změny/návrat,
  verification a nastavení poskytovatele. Autor schválil lesní zelenou v obou
  motivech a panely/zaoblení podle náhledu; viz `docs/design/r3/baseline.md`.
- E1/E2: připravené Electron UI scénáře, opakované workflow testy, lifecycle
  scénáře, package/build identity a packaged smoke/gate skripty. Úplný úspěch
  dosud není doložen. E3 dokumentace a přijetí nejsou dokončeny.

## Skutečné výsledky kontrol

- Poslední `npm.cmd run typecheck`: exit 0, po posledních produkčních opravách.
- Poslední `npm.cmd run lint`: exit 0, po posledních produkčních opravách.
- `check:deps`: před posledními drobnými změnami exit 0, 295 modulů / 884 vazeb;
  zopakovat v konečné bráně. `git diff --check` dříve exit 0.
- Poslední úplné `npm.cmd test`: NEÚSPĚCH, 4 neúspěšné / 83 úspěšných / 2
  přeskočené soubory; 5 neúspěšných / 596 úspěšných / 3 přeskočené testy.
  Dvě očekávání migrací nově zahrnují verzi 12, staré očekávání zrušení procesu
  nově očekává potvrzené zastavení. Dvě procesní selhání odhalila závod mezi
  nulovým Job accounting a signalizací procesního handle; oprava čeká na handle
  ve stejném dvousekundovém deadline. Celou sadu po opravách JE NUTNÉ znovu spustit.
- Cílené kontrakty, SQLite, stream/redakce, služby, sender/subscriptions/close,
  store/composer a runtime testy průběžně prošly. Reálné R3 runtime workflow:
  3 testy prošly po optimalizaci projektového lookup a souběžném idempotentním
  návratu; následná oprava dokončení auditního tool call ještě potřebuje retest.
- Windows secret store: 8 testů prošlo. Skutečný vývojový Electron 43.4.0 probe
  ověřil šifrování, restart/dešifrování, náhradu, poškození a odstranění.
  To není důkaz fungování zabalené aplikace.
- Command stream dříve prošel včetně havárie samotného hostu a zániku potomků
  do 2 sekund. Poslední úplná sada nicméně odhalila výše uvedený závod.
- Forge package se dvakrát podařil a Playwright skutečně spustil Electron a
  otevřel první okno. Aktuální build je po dalších opravách zastaralý.
- První UI workflow provedlo patch → schválení → úspěšný test → návrat baseline,
  ale následná auditní assertion chybně zahrnovala ruční revert. Filtr opraven,
  scénář není započítán jako úspěšný. Všech 20 opakování ještě neproběhlo.
- Packaged smoke selhal při čtení ASAR checksum přes virtuální Electron FS;
  opraveno synchronním čtením se scoped `process.noAsar`, ale zatím bez nového
  package/probe. Poslední package navíc skončil EBUSY v output adresáři.
- `verify:r3` dosud neproběhlo. Audit závislostí dříve hlásil 58 zranitelností,
  z toho 3 critical (baseline 54); nejsou vyhodnoceny ani automaticky opravovány.

## Pokračování — nepovažovat za finální release

1. Ověřit poslední procesní, SQLite a R3 workflow opravy; potom celou sadu,
   typecheck, lint a dependency gate. Neoslabovat ochranu externích změn.
2. Zkontrolovat startup failure IPC fallback: i větev chybného startu musí
   validovat sender a vstup stejně jako běžný handler. Prověřit test profile
   canonical/junction boundary a chybovou kategorii factory failure.
3. Dokončit UI požadavky: dostupné R0 diagnostiky, návrat z busy settings do
   běhu, retry přes editovatelný draft; prověřit reset starších activity stránek
   při refresh a rozhraní na 900/1280/1440 px.
4. Dokončit adverse testy: persistent stream/secret scan, HTML escapování,
   101+ aktivit v DOM, verze/fault/race secret store a actual Electron host-only
   crash během příkazu i modelového streamu. Prověřit truncation metadata.
5. Znovu sestavit package, ověřit ASAR/build identity a všechny packaged secret,
   workflow Git/non-Git a cancellation fáze; opakovat všech 20 UI workflow.
   Nezaměnit starý package za aktuální důkaz.
6. Dokončit E3: README, acceptance/checklist, architekturu a evidence templates.
   Pět čerstvých live pokusů AC-O1-04 a osobní autorský checklist nejsou splněny.
   R4/R5 schopnosti zůstávají mimo rozsah.
7. Až po skutečném průchodu celé brány označit implementaci dokončenou;
   autorovo přijetí a případný merge vyžadují vlastní příslušné zadání.

Lokální `.r3-artifacts` a `.playwright-mcp` jsou ignorované a nejsou v checkpointu.
