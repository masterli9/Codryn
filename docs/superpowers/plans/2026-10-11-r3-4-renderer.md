# R3.4 – React pracovní plocha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Zpřístupnit projektový chat, průběh, oprávnění, diff, ověření a nastavení v jedné čitelné pracovní ploše.

**Architecture:** React komponenty používají omezený preload klient a obnovují backendovou projekci. Místní state obsahuje jen navigaci, rozepsaný vstup, focus, motiv a otevřené detaily.

**Tech Stack:** React/TypeScript přes existující Forge/Webpack, lokální font, Vitest DOM testy a Playwright MCP pro vizuální QA.

**Spec:** [R3 specifikace](../specs/2026-10-11-r3-electron-workspace-design.md), §1/4/7/8.

## Global Constraints

Platí [R3 index](2026-10-11-r3-implementation.md). D1 vyžaduje A/C kontrakty,
D3/D4 potřebují běžící B/C. D2 je návrhová brána před finálním vzhledem.
Žádné falešné badge úspěchu, nefunkční @/terminál, Lucide nebo vzdálené fonty.

## Review Focus

Odpověď ze starého chatu (D1), český text a úzké okno (D2), IME a
rozepsaný vstup (D3), secret v React state po uložení (D4), stale ověření
a neúspěšný stop zaměněný za hotovo (D3/D4).

Povinné D3/1/3/4: RunStatus čte backendovou phase a failure, takže čekání
na model, approval, nástroj a ověřování mají vlastní text i po reloadu.

settings. Z odkazu u starší zprávy lze otevřít run.inspect a stránkovat
run.activity; starší běh nesmí převzít výsledek nebo diff nového. Při novém
aktivním běhu zůstává Stop svázaný s ním, i když uživatel prohlíží historii.
Test 101 auditních událostí prokáže dosažitelnost nejstaršího rozhodnutí.
Ctrl/IME/dlouhý český text, chyba submit a jeho bezpečné opakování zachovají
vstup a správné requestId; žádný duplicitní běh při ztracené IPC odpovědi.
