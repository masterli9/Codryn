# R3 E3 — skutečný packaged vizuální a klávesnicový průchod

Datum: 1. listopadu 2026. Automatický offline důkaz; osobní přijetí autora
zůstává neprovedené. Produkční kód ani testy se při tomto průchodu neměnily.

Ověřena byla skutečná zabalená Windows aplikace, nikoli komponenty se
syntetickým IPC. Zdrojový hash před i po bězích je
`82eebf763379e3d9d094e7f97359968dddc095d308f5c16e563319836238b388`,
ASAR `630361f2b1bb19b6757094eb5f2dfde2a2c1b70af56700fcdf7e48c6dc445773`,
exe `6aae3c142a09d1bf0d71307aec50121d9bca412a3c717a3e5513d6b3cf4e1224`.
`verifyBuild()` porovnal aktuální zdroje, zámek závislostí i balíček se
záznamem sestavení před a po každém běhu.

## Provedení a výsledky

Playwright MCP neposkytuje řízení životního cyklu skutečného Electron procesu;
použit je již instalovaný Playwright `_electron` a existující pomocníci
`tests/support/src/r3-desktop.ts` a `r2-project.ts`. Nebyly instalovány závislosti,
oslabovány CSP, sandbox ani oprávnění rendereru. První start v sandboxu hostitele
selhal; následné hostní spuštění se schválenou eskalací fungovalo.

Hlavní scénář použil deterministické demo nad novou non-Git fixture: skutečné
čtení/zápis `sum.mjs`, schválení skutečného Node testu, ověřený výsledek, diff
a bezpečný návrat původního obsahu. Druhá fixture s vestavěným main-only scénářem
`two-patches` vytvořila částečné ověření; novější ruční změna na `return 99`
zastarala ověření a návrat skončil konfliktem při zachování novějšího obsahu.
Modelové odpovědi byly připravené; služby, IPC, persistence a operace byly skutečné.

| Stav | Skutečné snímky |
| --- | --- |
| Žádný projekt, prázdný chat, čekání na schválení | každý 3 rozměry × 2 motivy |
| Ověřený výsledek s diffem, vrácená změna | každý 3 × 2 |
| Částečné ověření, zastaralé ověření, konflikt návratu | každý 3 × 2 |
| Nastavení a chybějící klíč | 3 × 2 |
| Čekající model s průběžným textem, přerušený běh po restartu | každý 3 × 2 |
| Potvrzovací dialog návratu | 1440 × 900, tmavý |

Celkem **66 maticových snímků + 1 samostatný dialog = 67 unikátních PNG**.
Nastavení 1440 × 900 dark bylo také zachyceno v hlavním průchodu; doplněk je
přepsal stejnou scénou a do unikátního počtu se nepočítá dvakrát.
Rozměry odpovídají D2: **900 × 640, 1280 × 720, 1440 × 900**, oba motivy.
Měřen byl skutečný obsah Electron okna, nikoli pouze požadovaný resize.
V 66 variantách nenastalo horizontální přetečení dokumentu a oba dokončené
průchody zaznamenaly **0 page errors / 0 console errors**. Diff má vlastní
horizontální posuv; při 900 px je detail překryvem, který lze zavřít Escape.
Na minimální výšce je karta schválení vyšší než viditelný chat; tlačítka jsou
dosažitelná svislým posuvem a klávesnicí. Osobní čitelnost na projektoru není
tímto měřením potvrzena.

Klávesnicí Tab → Enter byly vykonány otevření projektu, založení chatu,
odeslání úkolu, povolení příkazu, otevření potvrzení návratu, potvrzení návratu,
nastavení a konfliktní návrat. Záznam obsahuje počty Tab a skutečný
`:focus-visible` s 3px obrysem. Escape zavřel nastavení i detail a vrátil focus
na původní ovladač. Další Enter na „Nový pokus“ obnovil editovatelný text po
přerušení; tento doplňkový krok použil přímé zaměření prvku, nikoli celý Tab tok.

Doplněk `interrupted-model` zobrazil skutečný průběžný text. Následovalo
`app.exit(77)` pouze vlastního ověřeného packaged procesu bez normálního
uzavření služeb; nový proces nad stejným profilem zobrazil přerušený běh a
nabídl nový pokus, bez tlačítka aktivního zastavení. Nejde o nový důkaz
Windows process-tree crash testu, který vlastní předchozí E2.

Kontrast byl spočítán z produkčních CSS barev pro 20 běžných kombinací:
text, sekundární text, primární tlačítko, warning/error/added, focus a okraj
vstupu. Všechny překročily příslušných 4,5 : 1 pro text a 3 : 1 pro ovládání.
Nejnižší zvolený textový poměr je 5,243 : 1; nejnižší poměr ovládání 3,720 : 1.
Jde o kontrolu uvedených tokenů, nikoli úplný audit všech stavů a průhledností.

## Omezení a nepovedené pozorování

Skutečný OS folder dialog a potvrzení zavření aplikace byly existujícím
pomocníkem nahrazeny jen v main procesu pevnou odpovědí; jejich osobní průchod
autorem zůstává povinný. Nebyl použit skutečný ani syntetický API klíč,
placený provider ani síťové volání. Nastavení ukazuje chybějící klíč;
nedostupné chráněné úložiště se tímto průchodem nově neprokázalo.

Další omezený scénář `tool-stream.mjs` se skutečným izolovaným procesem
zůstal **failed, 0 snímků**. První pozorovatel čekal na stdout text v DOM;
po uzavření byl očekávaný výstup dohledán v `command_outputs`, takže samotný
proces skutečně běžel. Druhý bounded pozorovatel nezachytil výstup v krátkém
DB okně. Příčina tohoto rozdílu není potvrzena. Tento extra běh neprokazuje
nové úspěšné klávesnicové zastavení ani screenshot skutečného command streamu;
není započten do úspěšné matice. Všechny jeho aplikace byly zavřeny v `finally`.

Z povinných návrhových stavů spec §7 zůstávají v tomto novém packaged
vizuálním záznamu nepokryté: samostatný projekt bez chatů mimo automatický
dialog založení, stabilní snímek ověřování a zastavování, reconnect,
samostatná obecná chyba, prázdné hledání, nedostupný projekt a nedostupný klíč.
Neověřený výsledek je vidět během approval a po návratu, není tu nový
samostatný dokončený unsupported-profile scénář. Běžící nástroj byl skutečně
spuštěn v hlavním toku, jeho stabilní samostatný screenshot se nezdařil.
Tento průchod tudíž **neuzavírá všechny obrazovky spec §7 ani celé E3**.

Při rámování snímků byly opraveny pouze pozorovatele QA: po skrytí detailu se
čeká na existenci verified badge a potom se detail otevře; snímek dále čeká
na dokončení načtení diffu. Původní timeout skrytého badge není produkční
regrese. Pokusy nejsou vydávány za jediný nepřerušený zelený gate.
